# ChatApp

A dating app built around real-time chat, built incrementally from the project's 500-feature issue backlog, one issue at a time via the `/next-issue` workflow. See `CLAUDE.md` for the product-direction note.

## Stack

- **Monorepo:** npm workspaces (`apps/*`, `packages/*`)
- **Web:** Next.js (App Router) + TypeScript, PWA-first
- **API:** Node.js + Express + Socket.io (real-time messaging)
- **Shared:** `@chatapp/shared` — types and constants shared between web and API

See `CLAUDE.md` for scope decisions and the issue-implementation workflow.

## Getting started

```bash
npm install
npm run dev:api   # http://localhost:4000
npm run dev:web   # http://localhost:3000
```

- #136 24-hour timer to respond to the first message before the Match expires (Bumble) — new `MatchExpiryStore` (`matchExpiry.ts`) starts a 24-hour clock the moment `POST /api/swipes` creates a match, stopped the moment either side sends a message to the other (via the same `recipient` field #135 introduced) — doesn't care which side was supposed to go first, that's #135's own separate rule; `GET /api/matches/:author` drops an expired match from the list entirely (same as real Bumble removing it), and a new `GET /api/matches/:author/:candidate/expiry` powers a live countdown; `message:send` also rejects further messages to an expired match; new `MatchCountdown` "⏳ Xh Xm Xs left to say something" component on `/matches`
- #137 Extend Match chat time (Bumble) — `MatchExpiryStore` gained `extend()`: either side can push #136's 24-hour deadline back by one more full window, but only once per match, only before it expires, and only before a first message has been sent (once a conversation starts there's no deadline left to extend); new `POST /api/matches/:author/:candidate/extend`, reflected in the existing expiry endpoint's `extended` flag; `MatchCountdown` now shows an "Extend +24h" button next to the live countdown, hidden once already used
- #138 Pin important chats to the top of the list (Bumble) — new `PinnedChatsStore` (`pinnedChats.ts`), a one-sided per-viewer pin list over the other side of a match, same shape as #45's `BlockStore` (pinning from your side doesn't pin it for them); new `POST`/`DELETE /api/pinned-chats` and `GET /api/pinned-chats/:viewerAuthor`; `/matches` gained a Pin/Unpin button per row, sorts pinned matches to the top of the list, and marks them with a 📌
- #139 Archive old chats (Bumble) — new `ArchivedChatsStore` (`archivedChats.ts`), a one-sided per-viewer archive list, same shape as #138's `PinnedChatsStore`; purely a list-visibility preference, doesn't touch matching or #136/#137's expiry timer; `GET /api/matches/:author` now excludes archived matches by default and includes them (tagged `archived: true`) when called with `?includeArchived=true`; new `POST`/`DELETE /api/archived-chats` and `GET /api/archived-chats/:viewerAuthor`; `/matches` gained an Archive/Unarchive button per row and a "Show archived (N)" toggle to review and restore them
- #140 Search within conversation text (Bumble) — new `searchMessages()` (`messageSearch.ts`), a case-insensitive substring match over a room's message text, excluding #134's deleted messages (their stored text is just a placeholder) and reusing the same mutual-block filter as the plain messages list; new `GET /api/rooms/:roomId/messages/search?q=...`; `ChatRoom.tsx` gained a 🔍 Search toggle with a results list that jumps to and highlights a match using the same scroll/highlight mechanism as the existing `?m=` deep link — same disclosed limitation: jumping only works if that message is already loaded into the current page of history
- #144 Automatically blur suspicious photos before the user opens them (Bumble) — new `isSenderPhotoSuspicious()` (`photoWarning.ts`) reuses #107's `fakeProfileDetector` report-count signal rather than a fabricated NSFW-image classifier this app has no vision model/API key for; `message:send` sets a new `ChatMessage.suspicious` flag on a plain `imageUrl` message (not #123's already tap-gated `selfDestructImageUrl`) from a sender with enough reports; `ChatRoom.tsx`'s new `SuspiciousPhoto` component blurs it behind a "⚠️ tap to view" warning instead of rendering it immediately, staying permanently viewable once revealed (unlike #123's destroy-on-view)
